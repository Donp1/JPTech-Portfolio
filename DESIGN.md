# Build My Premium Web and App Developer Portfolio

Act as a senior product designer, creative frontend developer, UX specialist and performance engineer. Design and build a complete, production-quality portfolio website for me as a professional web and mobile application developer.

My brand is currently called **JPtech**, but confirm the final brand name with me before implementation.

The portfolio must feel original, polished and memorable. It should demonstrate strong engineering ability while remaining professional, usable, accessible and fast.

Do not immediately start coding.

---

## Phase 1: Inspect the project

Before asking questions:

1. Inspect the existing repository and understand:
   - Current framework and project structure
   - Installed dependencies
   - Existing components
   - Existing design tokens
   - Fonts, icons and assets
   - Routing approach
   - Styling solution
   - Linting, formatting and testing configuration

2. Preserve useful existing architecture and components.

3. Do not overwrite working functionality or unrelated user changes.

4. If the project is empty, recommend an appropriate setup before creating it.

5. Use the repository’s existing package manager. Do not introduce a different package manager.

Before using any component:

1. Check its license.
2. Confirm compatibility with the project.
3. Review its dependencies.
4. Adapt its colors, spacing and typography to the portfolio’s design system.
5. Confirm that it works on mobile.
6. Confirm keyboard and screen-reader accessibility.
7. Check its effect on performance.
8. Avoid blindly pasting code.
9. Do not use a premium component unless I confirm that I own the necessary license.

The final site must have a cohesive visual system. It must not look like unrelated components copied from several websites.

- Laptop
- Desktop
- Wide desktop

- Horizontal scrolling
- Text clipping

- Broken navigation

## Accessibility

Target WCAG 2.2 AA where practical.

Ensure:

- Semantic HTML
- Logical heading hierarchy
- Keyboard navigation
- Visible focus states
- Appropriate ARIA usage
- Accessible form labels
- Meaningful alternative text
- Sufficient color contrast
- Accessible mobile navigation
- Reduced-motion support
- No interaction that depends only on hover
- No information communicated by color alone

---

## Performance

Prioritize performance from the beginning.

Requirements:

- Optimize and correctly size images.
- Avoid unnecessary client components.
- Use server components where suitable.
- Lazy-load heavy media and non-critical effects.
- Avoid large animation bundles for trivial interactions.
- Prevent cumulative layout shift.
- Use responsive image sizes.
- Subset or optimize fonts.
- Reduce unnecessary JavaScript.
- Avoid autoplay video unless justified.
- Provide lightweight fallbacks for complex visual effects.
- Keep scrolling smooth on ordinary mobile devices.

Do not sacrifice usability or performance merely to achieve an Awwwards-style appearance.

## Implementation workflow

After I approve the design direction:

1. Present the proposed sitemap.
2. Present the page and section hierarchy.
3. Present the component architecture.
4. Present the design-token direction.
5. Present the selected component libraries and explain why each is needed.
6. Identify any assets still required.
7. Create an implementation plan.
8. Implement in logical stages.
9. Show meaningful progress after each stage.
10. Verify each stage before moving forward.

Do not stop at a static mockup. Build the actual responsive website with working interactions and navigation.
